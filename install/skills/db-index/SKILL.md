# /db-index

**Invocation:** `/db-index [kb_path]`

Use this command to regenerate the knowledge base index at `db-knowledge/README.md`.
It scans the KB directory tree, collects all documented schemas and tables, and
rebuilds the index table — preserving the file's header and any manually written
context above the index.

---

## Behavior Overview

1. Locate the knowledge base directory
2. Scan for schema folders and table files
3. Parse each table file for its Purpose and metadata
4. Rebuild the index table in README.md
5. Confirm the update

---

## Step 1: Locate the Knowledge Base

The KB path is `db-knowledge/` by default. If `kb_path` was provided as an
argument, use it instead.

If the directory does not exist, stop and tell the user:
> "No knowledge base found at `db-knowledge/`. Run `/db-orient` or `/db-document` first to create KB entries."

---

## Step 2: Scan the Directory Tree

Walk the KB directory and collect:

**Schema-level entries** — any subdirectory that is not prefixed with `_` and is not
a top-level file. Each subdirectory is treated as a schema.

**For each schema directory, collect:**
- `_schema-overview.md` — schema-level overview (optional)
- All `{table_name}.md` files that do NOT start with `_`
- The `_queries/` subdirectory — note the count of `.sql` files if present

**Top-level files to handle specially:**
- `README.md` — this is the file we are regenerating, not a schema
- `_gotchas.md` — cross-schema gotchas, list in the index header section
- `_open-questions.md` — list in the index header section
- `_external-docs/` — note if present but do not recurse

---

## Step 3: Parse Each Table File

For each `{table_name}.md` file found, extract:

1. **Table name** — the filename without `.md`, converted to uppercase for display
2. **Last Documented date** — look for `**Last Documented:** YYYY-MM-DD` in the file
3. **Status** — look for `status: {draft|reviewed|trusted}` in YAML frontmatter, or `**Status:**` field; default to "draft" if not found
4. **Purpose (first sentence)** — find the `## Purpose` section and extract the first non-blank sentence (truncate at 100 characters with `…` if longer)

If a file cannot be parsed (empty, malformed), note it with:
> "⚠️ Could not parse `{schema}/{table_name}.md` — skipping from index"

And include the table in the index with `(parse error)` in the Purpose column.

---

## Step 4: Rebuild the Index

Produce the updated README.md content with this structure:

```markdown
# DB Knowledge Base

This directory contains the team's data dictionary for `{schema_scope}`.

**Contents:**
- {N} schema(s) documented
- {N} table(s) documented
- {N} canonical queries saved
- Last indexed: {today's date YYYY-MM-DD}

Cross-cutting files:
- [`_gotchas.md`](_gotchas.md) — known issues that apply across schemas
- [`_open-questions.md`](_open-questions.md) — unresolved questions

---

## Index

{For each schema, a subsection:}

### {SCHEMA_NAME}

{If _schema-overview.md exists: "📄 [Schema overview]({schema}/_schema-overview.md)"}
{If no overview: "*(No schema overview — run `/db-orient {schema}` to create one.)*"}

| Table | Purpose | Status | Last Documented | Queries |
|-------|---------|--------|-----------------|---------|
| [`{table_name}`]({schema}/{table_name}.md) | {first sentence of Purpose} | {draft\|reviewed\|trusted} | {YYYY-MM-DD or "—"} | {N queries or "—"} |

{Repeat for each table in the schema, sorted alphabetically}

---

{Repeat for each additional schema}

---

*Generated by `/db-index` on {today's date}. Edit table files to update — do not edit this index directly.*
```

**Rules for the index:**
- Tables sorted alphabetically within each schema
- Schemas sorted alphabetically
- If `_queries/` exists with `.sql` files, show the count as a number link: `[3]({schema}/_queries/)`
- If no queries, show `—`
- Status column values: `draft`, `reviewed`, `trusted` (match whatever is in the file)
- Missing metadata (no date, no status): show `—`

---

## Step 5: Write the Updated README

Before writing, read the existing `db-knowledge/README.md` to check for a
manually-written header section (content above the `## Index` heading or the
first H2 that contains a table).

**Preserve strategy:**
- If the existing README has content above `## Index` that is NOT the auto-generated
  header (i.e., it looks hand-written), preserve it verbatim above the new index
- If the file is entirely auto-generated (contains the `*Generated by /db-index*`
  footer), replace it entirely

Write the new content (UTF-8 encoding).

Confirm:
> "Updated `db-knowledge/README.md`. Indexed {N} schema(s), {N} table(s)."

If any parse errors occurred, list them:
> "⚠️ Could not parse the following files (included in index with placeholder text):
> - `{schema}/{table}.md`"

---

## Notes

- This command reads files only — it never modifies table files, only README.md
- Run this any time new table files are added, not just after `/db-document` — the hook `db-doc-prompt` will offer to run it automatically after a save
- If the KB directory is in a git repo, the analyst should commit the updated README alongside any new table files: `git add db-knowledge/ && git commit -m "Update KB: document {table_name}"`
- For large KBs (50+ tables), this command may produce a long README — consider whether a per-schema summary page would be more useful than a flat index (out of scope for this command)
